AI Gateway: tiers, limits and every capability

AI Gateway puts Azure API Management (APIM) between clients and your Foundry models and tools. It gives you per-project token limits and quotas, centralized policy, observability and a governed entry point for MCP tools and custom agents.

Limits apply per project on the shared gateway. Policies are enforced in API Management; the Foundry portal handles setup and token limits.

API Management tiers for AI Gateway

TierRole in Foundry AI Gateway (per the docs)
Basic v2What the portal creates when you choose Create new. Designed for development and testing with SLA support. Typically provisions in 5 to 10 minutes.
Standard v2Recommended for production or higher throughput when you bring an existing instance. For a private Foundry resource, use it with a private endpoint.
Premium v2Production and higher throughput. For a private Foundry resource, use it with a private endpoint, or injected into a virtual network.
Classic tiers (Developer, Basic, Standard, Premium) and ConsumptionNot selectable as an existing instance. When you choose Use existing APIM, only instances in a v2 tier appear, in the same Entra tenant and subscription as the Foundry resource.
Free tier. AI Gateway includes a free tier for Azure API Management; check API Management pricing for current details and eligibility. The general AI gateway capabilities in APIM apply across tiers, but individual capabilities vary by tier (for example the Anthropic Messages API is currently supported in the v2 tiers). You enable the gateway per Foundry resource; all its projects share it and its APIM instance, each with its own limits. For separate gateways (strict isolation or different networking), use separate Foundry resources.

Manage › AI Gateway › your gateway › Token management › + Set limit: choose the project and deployment, then enter a tokens-per-minute value.

TPM rate limit

Caps consumption per minute. Exceed it and the caller gets 429 Too Many Requests.

Total token quota

Caps consumption per period (hourly, daily, weekly, monthly or yearly). Exceed it and the caller gets 403 Forbidden.

  • Use it for multi-team containment, cost control by capping aggregate usage, and compliance ceilings.
  • Concurrent requests can briefly exceed a limit until responses are processed. New limits apply immediately to later requests.
  • If latency rises after enabling, compare against calling the model directly; check APIM region versus the resource region and cold start.
CapabilityHow APIM does it
Token rate limiting and quotasllm-token-limit policy: a TPM limit or a token quota over hour to year, on any counter key (subscription key, IP, or expression); can precalculate prompt tokens to skip calls that already exceed the limit.
Token metricsllm-emit-token-metric policy: emit consumption with custom dimensions to Application Insights and Azure Monitor.
Semantic cachingllm-semantic-cache-lookup and llm-semantic-cache-store with Azure Managed Redis (or a compatible RediSearch cache) and an embeddings API; reuses completions for similar prompts.
Load balancingBackend pool with round-robin, weighted, priority-based or session-aware balancing, for example prioritizing PTU backends.
Circuit breakerStops sending to unresponsive backends; trip duration follows the backend's Retry-After header.
LoggingLog tokens, prompts and completions for billing and audit; built-in dashboard in APIM.
ScaleAutomatic or manual scale units and regional gateways, depending on tier.
Developer experienceSelf-service for teams; credential manager for OAuth to APIs and MCP servers; unified model API (preview).
<!-- 500 tokens per minute per subscription key -->
<llm-token-limit counter-key="@(context.Subscription.Id)"
                 tokens-per-minute="500" estimate-prompt-tokens="false"
                 remaining-tokens-variable-name="remainingTokens" />

<!-- emit token metrics to Application Insights -->
<llm-emit-token-metric namespace="llm-metrics" />

Route MCP traffic through the gateway Preview for a single governed entry point with authentication, rate limits, IP restrictions and audit logging, without modifying your MCP servers or agent code.

  • Only new MCP tools created in the portal that do not use managed OAuth are routed through the gateway. The tool's endpoint then shows the APIM URL instead of the server URL.
  • Supported MCP auth: managed identity (Entra), key-based, custom OAuth identity passthrough, or unauthenticated where applicable.
  • Apply policies in APIM: rate limit, IP filter, correlation ID header, and removal of sensitive headers (Cookie, Referer).
  • Register custom agents from other platforms in the control plane and govern them through the same gateway.
  • Bring your own model: connect models hosted behind your own gateway (APIM or a non-Azure gateway) to Foundry Agent Service, keeping control of the endpoint.
<inbound>
  <base />
  <rate-limit-by-key calls="60" renewal-period="60" counter-key="@(context.Request.IpAddress)" />
  <set-header name="X-Correlation-Id" exists-action="override"><value>@(context.RequestId)</value></set-header>
</inbound>
