Toolbox, tool catalog and connectors

Agents become useful when they can act. Instead of wiring every tool, credential and policy into every agent, a Toolbox lets you define a curated set of tools once and expose them through a single MCP-compatible endpoint any agent can consume.

Toolboxes are created in Foundry but are not Foundry-bound: any MCP-compatible runtime or client can use one.

BuildCreate reusable collections of tools and skills; configure auth once.
DiscoverTool search Preview exposes two meta-tools (tool_search, call_tool) so hundreds of tools do not flood the context.
ConsumeConnect agents to a single endpoint; add or reconfigure tools without redeploying agents.
GovernApply authentication, guardrails, observability and version management at the toolbox level.

The tool catalog includes 1,000+ connectors to SaaS, data and line-of-business systems Preview. Adding one makes Foundry create a managed MCP server in your account's Connector Namespace, so you write no server code.

  1. BrowseFind the connector in the Tools catalog (Build › Tools).
  2. ConnectAuthenticate to the service (API key, OAuth account or personal access token).
  3. Select actionsChoose which actions to expose as MCP tools.
  4. Add toolFoundry creates the managed MCP server and adds it to your agent or toolbox.

Only actions are supported (no triggers). Managed MCP servers are scoped to the project where they are created and available in a defined list of regions. You need the Foundry Project Manager role on the project.

  • Custom MCP: Build › Tools › Custom › Model Context Protocol, then paste your endpoint and pick an auth type. Build your own MCP server if none exists.
  • Private tool catalog: publish approved tools for your organization to discover and reuse. A private skill catalog is also available in preview.
  • Skills Preview: versioned, immutable, multi-step workflows packaged as capabilities. Tools define what an agent can do; skills define how.

The toolbox handles credential injection, token refresh and policy enforcement at run time, so consuming agents do not manage per-tool secrets.

  • Microsoft Entra ID and OAuth identity passthrough (user delegation) for tools that act on behalf of a user.
  • Agent identity for autonomous or background work.
  • Key-based where a tool requires it, stored through a Key Vault connection rather than in code.

Treat tools as a supply chain. Third-party MCP servers are Non-Microsoft Products; vet them, review data sharing, and require approvals for risky actions.

  • Route new MCP tools through an AI gateway Preview to enforce authentication, rate limits, IP restrictions and audit logging without changing the MCP server or agent code.
  • Apply guardrails to tool calls and tool responses at the toolbox.
  • Version toolboxes and promote a new default only after testing.
