Governance: identity, policy, compliance and the control plane

As you move from isolated copilots to fleets of autonomous agents, you need one place to see them, set the rules and prove compliance. Foundry layers identity, network, data protection, policy and security signals, and surfaces them in the Foundry Control Plane Preview.

People

Microsoft Entra ID and Azure RBAC with Foundry roles that separate control plane from data plane (User, Project Manager, Account Owner, Owner). Prefer keyless authentication. Elevated-role tasks and the option to disable preview features are documented for administrators.

Agents

Each agent gets a Microsoft Entra agent identity under an agent identity blueprint. It starts with no permissions; you grant least-privilege RBAC on the target services. Agents authenticate to tools without secrets in prompts or code.

Callers

Agent endpoint authorization controls who can call an agent (Azure RBAC, agent blueprint, Bot Service schemes). API keys are not supported for agent endpoints.

Users, delegated

User delegation for tools uses OAuth on-behalf-of and Microsoft Entra consent so tools act with the user's permissions, not a broad service identity.

  • Network: choose a networking option, then configure private link or a managed virtual network; reach on-premises resources; add Foundry to a network security perimeter. Hosted agents and the publishing flow have virtual-network paths.
  • Encryption: understand and configure customer-managed keys.
  • Secrets: store them in your own Azure Key Vault through a connection; rotate API access keys where keys still exist.
  • Data residency: data at rest stays in the chosen geography; processing depends on the deployment type (global, data zone, regional).
  • Standard agent setup: keep agent files, vector stores and conversation state in your own Storage, AI Search and Cosmos DB.
  • Built-in policy definitions for AI services and Foundry, plus a built-in policy for model deployment (control which models may be deployed) and custom policy definitions.
  • Govern model router with Azure Policy to restrict which models it may route to.
  • Guardrail policies mandate minimum guardrail controls for deployments across a subscription or resource group.
  • Creating or editing guardrail policies needs Owner or Resource Policy Contributor at subscription or resource-group scope. Most users can still view compliance status.

Operate › Compliance. Use the subscription and project filters first, then switch tabs.

Together they address prompt injection, sensitive data leakage and model misuse in a defense-in-depth model, and alerts appear on the control plane dashboard.

  • Manage agents at scale across supported platforms: filter, drill into evaluation and monitoring, act on recommendations.
  • Register custom agents from other platforms into the control plane registry (preview) and route them through the AI gateway.
  • Agent availability for administrators: use Agent 365 and Microsoft Entra governance actions, with Azure infrastructure intervention as the emergency path.
  • Schedule red-team scans and drift monitoring for ongoing agent testing.
  • Transparency notes for Azure OpenAI and for Foundry Agent Service; data, privacy and security pages for models and agents; a code of conduct; abuse monitoring; content provenance and text watermarking for supported models.
  • High availability and disaster recovery guidance, including recovery from platform outage and from resource and data loss, and a Foundry security baseline.
  • Model lifecycle: track retirement dates so a governed fleet does not depend on a retired model.
