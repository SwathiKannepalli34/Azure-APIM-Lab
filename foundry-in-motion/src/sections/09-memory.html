Memory: agents that remember

Memory is a managed, long-term store that lets an agent keep user preferences, facts and context across sessions, devices and workflows. Short-term memory covers the current conversation; Foundry memory is built for the long term.

Extraction, consolidation and retrieval run behind the scenes. An LLM merges overlapping facts and resolves conflicts, such as a newly mentioned allergy, so the store stays accurate.

Three kinds of long-term memory

TypeWhat it holdsRetrieve…
User profileDurable preferences and personal context: language, defaults, accessibility needs.Near the start of each conversation, for stable personalization.
Chat summaryDistilled summaries of earlier topics and threads.Per turn, using the current messages, for continuity.
ProceduralReusable how-to routines and patterns inferred from prior interactions.When the user asks for a recurring workflow the agent has handled before.

Memory search tool

Attach it to a prompt agent so the agent reads from and writes to the store during conversations. This is the simplest and recommended path. Scope can be resolved automatically from the caller with {{$userId}}.

Memory store APIs

Low-level control over individual memory records, retention and explicit lifecycle operations. You must set the scope explicitly in every request.

Hosted agents can add persistent memory too (see the hosted agent quickstart), and LangChain and LangGraph can use Foundry Memory.

  • Item-level CRUD: create, read, update, list and delete individual memories.
  • Store-level default retention: a default TTL in seconds for new entries, set at store creation.
  • Direct commands: immediate remember-or-forget when users ask.
  • Each type (user profile, chat summary, procedural) can be enabled or disabled when you create a store.

Because an LLM extracts and consolidates memories from conversations, incorrect or harmful content can be stored and later steer the agent (prompt injection, memory corruption). Mitigate by:

  • Using Azure AI Content Safety and prompt-injection detection on content entering and leaving the memory system.
  • Regularly stress-testing the agent with controlled adversarial exercises (AI red teaming).
  • Keeping per-user scopes so one user's memories never reach another.
