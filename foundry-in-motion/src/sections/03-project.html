03 · Your first step

Create a Foundry project

A project organizes agents, evaluations and files. It lives on a Foundry resource, which the portal creates for you. One resource can hold many projects that share its networking, policy and gateway.

Many projects, one resource: shared models, networking and governance, separate agents and project-level access.

  1. Sign in to Microsoft FoundryMake sure the New Foundry toggle is on. You need an Azure subscription and a role that can create a Foundry resource, such as Foundry Account Owner or Foundry Owner on the subscription or resource group.
  2. Select the project name (upper left), then Create new projectGive it a name and select Create project.
  3. Optional: advanced optionsPick an existing resource group or create a new one (recommended when starting, so you can manage and delete everything together), and choose the Location where project resources are hosted.
  4. Wait for provisioning, then copy the project endpointThe welcome screen shows it in the form https://<resource>.services.ai.azure.com/api/projects/<project>. Deploy a model next (Discover › Model catalog › Deploy).
The portal path uses basic defaults. If your organization needs custom names, security controls or cost tags that satisfy Azure Policy, use the Azure portal or a template instead.

Create the resource, then a default project. Requires azure-identity and azure-mgmt-cognitiveservices>=13.7.0 and an az login session.

from azure.identity import DefaultAzureCredential
from azure.mgmt.cognitiveservices import CognitiveServicesManagementClient

client = CognitiveServicesManagementClient(
    credential=DefaultAzureCredential(),
    subscription_id="<subscription-id>",
    api_version="2025-04-01-preview",
)

# 1) Foundry resource
client.accounts.begin_create(
    resource_group_name="<rg>", account_name="<foundry-resource>",
    account={
        "location": "eastus", "kind": "AIServices", "sku": {"name": "S0"},
        "identity": {"type": "SystemAssigned"},
        "properties": {"allowProjectManagement": True,
                       "customSubDomainName": "<foundry-resource>"},
    },
).result()

# 2) Project on that resource
client.projects.begin_create(
    resource_group_name="<rg>", account_name="<foundry-resource>",
    project_name="<project>",
    project={"location": "eastus", "identity": {"type": "SystemAssigned"}, "properties": {}},
).result()

Foundry roles separate control plane from data plane. Assign the least privilege that fits the job.

RoleUse it for
Foundry UserLeast-privilege role for developers building and testing agents; data actions on the project.
Foundry Project ManagerManage projects, build, and conditionally assign Foundry User to others.
Foundry Account OwnerFull access to manage projects and resources; can conditionally assign Foundry User, ACR and monitoring roles.
Foundry OwnerAccount Owner plus building with projects; highly privileged, self-serve.
Renamed roles. Foundry User, Owner, Account Owner and Project Manager were previously Azure AI User, Owner, Account Owner and Project Manager. Role IDs and core permissions are unchanged, and you may still see the old names while the rename rolls out.

For a team, you need a role that can assign roles (such as Owner) plus the email addresses or Entra security group IDs of the members.

Basic agent setup uses Microsoft-managed resources. Standard agent setup stores agent state in your own single-tenant Azure resources, for full data sovereignty and project-level isolation:

Bring your ownWhat it stores
Azure StorageFiles uploaded by developers and end users
Azure AI SearchVector stores created by agents
Azure Cosmos DB for NoSQLMessages, conversation history and agent metadata (at least 3000 RU/s)
Azure Key VaultSecrets management

Pair it with network isolation (private link or managed virtual network) when you need to keep traffic off the public internet.
