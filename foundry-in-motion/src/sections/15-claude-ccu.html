15 · Claude consumption units

What a CCU is and how to optimize it

Claude models in Foundry are billed in Claude Consumption Units (CCUs): a billing unit shared with Anthropic's other cloud platforms. CCU is billing only. You still call Claude with tokens and size workloads in tokens per minute, so the way to optimize CCUs is to optimize tokens.

1 · Pick the right model

Match the model to the task. Claude models range across Haiku, Sonnet, Opus and preview families; the docs note that Opus 5.5 has lower per-token prices and less expensive cache reads. Use model router in Cost mode to route simple prompts to cheaper models (deploy Claude first so it can be routed to).

2 · Control thinking with effort

Newer Claude models use adaptive thinking (the only thinking mode on 4.7 and later) and an effort parameter that trades thoroughness for token efficiency. Lower effort for routine steps; raise it only where quality needs it. Some models also support token budgets (task_budget) and per-turn effort.

3 · Cache what repeats

Prompt caching (5-minute and 1-hour) reduces cost and latency for repeated context. Automatic prompt caching caches the last cacheable block with one parameter and moves the cache point as conversations grow. Cache reads do not count toward your input tokens-per-minute quota.

4 · Keep context lean

Context editing clears old tool results and manages thinking blocks automatically. Tool search loads tools on demand (regex and BM25) so thousands of tools do not fill the window. Use token counting to know a prompt's size before you send it.

5 · Retrieve less, better

Ground with a focused knowledge base (Foundry IQ) and cap retrieval. Smaller, more relevant context is fewer input tokens on every call.

6 · Operate with discipline

Retry 429s with exponential backoff, track token use and request patterns, and use the least expensive suitable model. Monitor per-model tokens in the Foundry Monitor tab.

7 · Optimize the commercial side

Ask your Microsoft or Anthropic team about a Marketplace private offer for per-model discounts, and remember CCU counts against MACC.

8 · Optimize the agent itself

Use the agent optimizer to shorten and sharpen instructions and tool descriptions, and to compare models on quality versus cost against your dataset.

CCU does not change how you size Claude workloads. Plan with RPM, ITPM (uncached input tokens per minute) and OTPM (output tokens per minute), per model.

  • Subscription-level pools. All Global Standard deployments of the same model and version in a subscription share one quota pool across regions. Data Zone Standard deployments share a pool within each data zone (for example the US zone).
  • Cache-aware ITPM. For most Claude models only uncached input counts: input after the last cache breakpoint plus cache-creation tokens (5-minute or 1-hour). Cache-read tokens do not count, which makes caching a throughput lever as well as a cost lever.
  • Default limits depend on your subscription type (pay-as-you-go, Enterprise and MCA-E, Free Trial). Some preview models start at zero until you request quota.
