Publish agents to Microsoft Copilot and Teams

You publish the agent's stable endpoint, so end users always talk to one consistent agent while you roll out new versions behind it. Foundry builds the Teams app package and submits it for you.

  1. Test thoroughly in the portalConfirm responses and every tool work as expected.
  2. Select the active versionDetails tab › Agent configuration › Active version › Edit, or from the Publish button. Choose Always use latest or pin a specific version (recommended for production).
  3. Select Publish › Teams and Microsoft CopilotAn Azure Bot Service resource is created automatically, or shown read-only if one exists.
  4. Complete the metadataName, a three-part publish version (major.minor.patch), short description, description and developer. Optionally add website, terms of use and privacy statement URLs (HTTPS).
  5. Choose the scopeJust you, or people in your organization.
  6. Get admin approval if you chose organization scopeAfter approval the agent appears for everyone in your tenant under Built by your org.
  • Foundry User role on the project to create, manage and publish agents.
  • Azure Bot Service Contributor (or Contributor or Owner) on the resource group, to create the bot and configure its channels. Foundry roles do not grant these permissions.
  • Register the provider: az provider register --namespace Microsoft.BotService.
  • An agent version you tested and want to publish.
Microsoft 365 and Teams process and store some data about the published agent and its responses, under their own compliance and data-residency terms. Check that this fits your governance requirements before publishing.

Use the REST API and enable the source-IP-filtered public Activity Protocol route with enable_m365_public_endpoint; requests must come from Azure Bot Service or Microsoft 365 source ranges and still satisfy authorization.
  • Hosted agents built on the Responses protocol are bridged to the Activity protocol automatically for channel delivery. Interactive calls can use OAuth on-behalf-of flows; background calls use the agent's own Entra identity.
  • You can also publish an agent as an autopilot in Agent 365.
