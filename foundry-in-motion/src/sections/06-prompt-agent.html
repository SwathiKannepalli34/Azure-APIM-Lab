06 · Declarative agents

Create a prompt agent

A prompt agent is defined entirely by a model, instructions and tools. Foundry hosts and runs it, so there is no code or container to maintain. Every change creates a new immutable version served through a stable endpoint.

Agent = reusable behavior. Conversation = server-side history. Response = one execution. Start with a response, then add an agent and a conversation as you need them.

  1. Deploy a modelAn agent needs a deployed model. Any Foundry direct model works; gpt-5-mini is used in the quickstart.
  2. Build › Agents › CreateName the agent and choose the model deployment.
  3. Write instructionsDefine role, tone, what the agent must and must not do, and how to use its tools. Keep them specific and testable.
  4. Add tools and knowledgeAttach a toolbox, MCP servers, file search, Foundry IQ, memory, web search, code interpreter and more (see the tools section).
  5. Test in the playgroundChat, inspect tool calls, adjust, and save. Each save is a new version.
  6. Evaluate, then shareRun an evaluation, add a guardrail, then Publish to Teams and Microsoft Copilot or call the endpoint from your app.

Install azure-ai-projects>=2.3.0 (the 2.x SDK targets the current portal; it is not compatible with 1.x) and sign in with az login.

from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import PromptAgentDefinition

project = AIProjectClient(
    endpoint="https://<resource>.services.ai.azure.com/api/projects/<project>",
    credential=DefaultAzureCredential(),
)

# Create (or update) the agent: every call produces a new immutable version
agent = project.agents.create_version(
    agent_name="my-agent",
    definition=PromptAgentDefinition(
        model="gpt-5-mini",
        instructions="You are a helpful assistant that answers general questions",
    ),
)

# Chat with it over the Responses API, with server-side conversation state
openai = project.get_openai_client(agent_name="my-agent")
conversation = openai.conversations.create()
reply = openai.responses.create(conversation=conversation.id, input="Hello!")
print(reply.output_text)

The same flow exists for C#, TypeScript, Java and REST.

Voice-based prompt agents

Real-time spoken experiences. Configure the model, instructions, audio settings, an optional greeting and tools; connect through Voice Live. Foundry manages lifecycle and voice orchestration. Telephony channels, image input in a turn, sub-agents and voice-specific optimization are documented.

Workflows Preview

Orchestrate several agents and steps when one task spans more than one agent. If a single agent with tools can finish the job, keep it simple. Declarative workflows can also be used and migrated in VS Code.

Agent-to-agent (A2A)

Agents can delegate to other agents. A2A v1.0 is generally available; v0.3 is preview. You can enable incoming A2A on a Foundry agent so other agents can call it.

Routines Preview

Trigger agent work from schedules and events rather than only from user messages.

Every agent gets a stable endpoint. It is live from creation, and you do not need to publish for programmatic access.

  • Version routing. By default 100% of traffic goes to the latest version. Pin a version with a version_selector when an agent is in production or published.
  • Inbound auth. Azure RBAC (Entra) by default, plus agent-blueprint and Bot Service schemes used when publishing. API key authentication is not supported for agent endpoints.
  • Classic migration. Assistants-style agents move to the new agent model and the Responses API.
  • Keep instructions short, concrete and verifiable. Put long reference content in a knowledge source, not in the prompt.
  • Describe when to use each tool and what its parameters mean; vague tool descriptions are a common cause of wrong tool calls.
  • Prefer one agent with the right tools over a multi-agent workflow until you need orchestration.
  • Build an evaluation dataset early so every change is measured, not anecdotal.
  • Let the agent optimizer propose better instructions and tool descriptions against your dataset (next sections).
