14 · Know what you pay for

Cost options, tokens and provisioned throughput (PTUs)

Foundry has no single price. It is a set of optional Azure services, so you pay for what you use: model tokens or reserved capacity, hosted agent runtime, search, storage, monitoring and more. This section explains the levers and gives you a calculator.

Foundry has no page of its own in the Azure pricing calculator because it is composed of several optional services. Add each service you use (for example Azure AI Search, Speech or Language) and compare your estimate with Cost Management meters after a small test.

Tokens: the unit of everything

Language and vision models break input into tokens. Text, image and audio workloads can all be metered in tokens, and the billing unit and rate vary by model, deployment type and meter. Quotas are expressed as tokens per minute (TPM) and requests per minute (RPM).

PTUs: reserved capacity

A provisioned throughput unit (PTU) is a fixed amount of model processing capacity held exclusively for your deployment, whether or not requests are being made. That gives predictable throughput and latency, instead of the shared capacity (and variable throughput) of standard deployments.

Model-independentThe same PTU quota can deploy any supported model. You do not buy PTUs per model.
Region-specificQuota is per subscription, per region and per deployment type. East US quota does not carry to West Europe.
Throughput varies by modelA heavier model needs more PTUs for the same TPM. Each model has a minimum PTU count.

Quota

The maximum PTUs you may deploy per subscription, region and deployment type. A policy limit with no cost. Request more through the quota form (also on the Foundry quota page); approval can take several days.

Capacity

The PTUs actually available to deploy right now for a model version. Having quota does not guarantee capacity: if the region is short, creation fails. Check availability in the deployment experience or the model capacities API before you plan or buy a reservation.

Three factors turn your traffic into a PTU count:

  1. Request shapeRequests per minute, average input tokens and average output tokens.
  2. Output-to-input ratioOutput tokens need more capacity than input tokens. Each model has a ratio that expresses how many input tokens one output token is equivalent to.
  3. Cache rateThe fraction of input served from prompt cache. Cached tokens do not consume PTU capacity, so a higher cache rate lowers the PTUs you need.

The calculation normalizes these into one TPM figure and divides by the model's input-TPM-per-PTU value. Use the capacity calculator in the Foundry portal for a guided estimate.

  • Hourly billing is flexible but not intended for steady production. A deployment that exists for 15 minutes is charged one quarter of the hourly rate.
  • Azure Reservations give a discounted rate for a term commitment. Global reservations are not region-specific; Data Zone and Regional reservations are tied to the deployment's region.
  • If deployed PTUs exceed the reservation quantity, the excess is billed at the hourly rate.
  • Reservations can be canceled or exchanged, which might incur fees.

Spillover routes overage from a fully used provisioned deployment to a standard deployment, instead of returning 429.

  • Whole deployment: set spilloverDeploymentName on the provisioned deployment to a standard deployment of the same model and version in the same resource.
  • Per request: send the x-ms-spillover-deployment header. If spillover occurs, the response carries x-ms-spillover-from-deployment.
  • If both are set, the deployment property wins.

Choose PTU when…

  • Traffic is predictable and you can estimate RPM and token volumes.
  • Users or systems need consistent, low latency.
  • Volume is high enough that per-token billing gets expensive.
  • It is a real-time experience: chat, copilots or agents.

Stay on pay as you go when…

  • You are developing, testing or low volume.
  • Traffic is highly variable and hard to size.
  • You can combine both: provisioned for the baseline plus spillover for bursts.

Trim tokensShorter instructions, fewer tool definitions (tool search), tighter retrieval, and output limits.
