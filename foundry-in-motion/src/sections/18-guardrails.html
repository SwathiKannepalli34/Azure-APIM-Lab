18 · Safety at run time

Guardrails and controls

A guardrail is a named collection of controls. Each control defines a risk to detect, the intervention points to scan, and the action to take. Guardrails apply to models and, for agents, at four intervention points that cover the whole agent loop.

Guardrails applied only at the model leave tool traffic exposed. Agent guardrails close that gap. Each active intervention point adds roughly 50 to 100 ms of latency.

Tool call and tool response controls need moderation support from the tool itself. Supported today: Azure AI Search, Azure Functions, OpenAPI, SharePoint grounding, Fabric data agent, Bing grounding, Bing Custom Search and Browser Automation.

Blocking level (content harms)Blocks
OffNothing (may still annotate). Off for inputs is available to all; off for outputs needs approval for modified guardrails.
LowHigh-severity only. Least restrictive.
MediumMedium and high severity.
HighLow, medium and high severity. Most restrictive.
  • Actions: Annotate (models only) or Annotate and block (models and agents).
  • Override rule: an agent uses the guardrail assigned to the agent; it fully overrides the model's guardrail. If the agent's guardrail has no control for a risk at a point, that point is not scanned for it.
  • Classification models can produce false positives and negatives: evaluate controls with content representative of your workload.

Foundry Models include DefaultV2 safety by default, for every model except transcription models.

  • Core harm filters (hate and fairness, violence, sexual, self-harm) are on, at Medium, for prompts and completions.
  • User prompt attack (jailbreak) detection is on for prompts; protected material (text and code) is on for completions.
  • Document attack detection is off by default and must be enabled.
  • Blocked input returns an error response; blocked output can return a filtered completion.
Claude has no built-in deployment-time filtering in Foundry. Configure Azure AI Content Safety during inference for Claude and other partner models.
  1. Open Build › Guardrails (or Operate › Compliance)You need the Foundry Account Owner role.
  2. Create a guardrail and add controlsFor each: choose the risk, intervention point (for example Indirect attack at Tool response), action and blocking level. A Guided Guardrail experience is in preview.
  3. Assign itOne guardrail can apply to many models and many agents in a project. Controls not relevant to models (tool call, tool response) simply do not run on them.
  4. Test, then evaluateProbe with the AI Red Teaming Agent and run safety evaluators.
  5. Enforce fleet-wideUse guardrail policies (Azure Policy) to mandate minimum controls across a subscription or resource group (governance section).
